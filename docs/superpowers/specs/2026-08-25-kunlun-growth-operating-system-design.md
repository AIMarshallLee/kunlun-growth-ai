# 昆仑增长AI增长操作系统设计

**状态：** 可执行设计

**北极星目标：** 在未来12个月形成30个真实验证、可安装交付的 Skill/Agent 产品，服务1,000名付费客户或学员，并以可复用交付和成果案例形成商业闭环。

## 1. 设计原则

1. **先证明价值，再扩展目录。** 未经真实用户使用验证的内容只能是候补页或意向登记，不能计入30个产品，也不能收款或承诺交付。
2. **售卖的是可复用交付，不是提示词。** 每个产品固定包含 Skill、教程、模板、示例、安装说明、变更记录和人工边界。
3. **人工服务不是漏洞，是验证引擎。** 前90天保留人工确认、人工交付和人工回访；将重复问题沉淀为产品，而非过早做自动化。
4. **不收集不必要的数据。** 不要求 API Key、客户隐私、订单、Cookie 或支付信息；所有真实客户资料只在获授权的团队系统中处理。
5. **不把增长指标写成客户承诺。** 所有商业结果、平台审核、转化、合规结论均须经人工审核，不写入产品效果承诺。

## 2. 业务飞轮

```text
公开教程 / 案例 / 公开工具
        ↓
Skill 小课包详情页（适配判断 + 边界）
        ↓
人工咨询 / 课程权益登记
        ↓
版本化交付 + 首次运行支持
        ↓
首次成功、问题、未成交原因
        ↓
FAQ、模板、案例与下一批 Skill
        └──────────────────────→ 公开教程 / 案例
```

漏斗的唯一事实来源由团队维护的受控台账承担；网站只负责公开内容和不含敏感信息的联系意向。

平台同时运行两条获客与交付路径：

| 路径 | 面向对象 | 交付形式 | 作用 |
|---|---|---|---|
| 自助路径 | 跨境电商从业者、服务商、课程学员 | Skill 小课包、教程、模板、人工权益核验 | 扩大触达，验证高频任务，沉淀可复用产品 |
| 协作路径 | 教育机构、跨境团队及企业负责人 | AI 场景诊断、7天验证项目、团队培训、后续顾问服务 | 用真实业务问题验证 Agent 方法，形成高价值案例和可产品化模块 |

协作路径必须使用客户授权的数据环境和明确的人工审核点。公开站点只展示经授权且去敏的案例范围，不托管企业数据、密钥或业务系统凭据。

## 3. 产品组合与30个验证口径

产品按两条主线建设：跨境电商18个、教育12个。每一个产品必须先经过以下门槛，才可计数为“真实验证”：

| 门槛 | 必要证据 |
|---|---|
| 内容完整 | `SKILL.md`、`INSTALL.md`、模板、去敏示例、版本与变更记录齐全 |
| 安全检查 | 自动检查未发现密钥、客户数据、Cookie、令牌或未知二进制文件 |
| 目标工具演练 | 在声明支持的工具中，从安装到主要输出完成一次留痕演练 |
| 外部使用 | 至少3位非开发人员完成首次运行，或至少1次付费交付并完成首次运行 |
| 质量门槛 | 首次运行成功率不低于70%；不通过项进入修复，不以“已验证”对外销售 |
| 回收闭环 | 记录至少1条结构化反馈、1个FAQ或1项产品改进 |

## 4. 12个月分段目标

| 阶段 | 时间 | 产品结果 | 客户/学员结果 | 通过门槛 |
|---|---|---|---|---|
| 验证期 | 第1–3月 | 3个可售，6个候补 | 10个首批交付用户，3个可公开成果案例 | 咨询到有效对话≥3%，首次运行≥70% |
| 复制期 | 第4–6月 | 累计13个已验证产品 | 累计200名付费客户或学员 | 人工交付SOP稳定，重复问题可被FAQ/模板消化 |
| 扩张期 | 第7–9月 | 累计22个已验证产品 | 累计550名付费客户或学员 | 至少2条稳定获客来源，形成教育首个独立产品线 |
| 规模期 | 第10–12月 | 累计30个已验证产品 | 累计1,000名付费客户或学员 | 更新、案例、续购和服务交付形成闭环 |

每个阶段的目标是内部经营目标；若证据不足，延后计数和扩张，不通过降低标准来“完成数字”。

## 5. 首个90天的实施范围

### 第1–30天：让第一笔可复用交付跑通

- 完成商品素材生产包的非开发者首次运行演练，并修订安装与FAQ。
- 把 Listing 本地化、媒体质检从候补页推进到真实演练，不在通过前开放交付。
- 配置业务收件邮箱，启用人工邮件咨询；建立团队内部台账。
- 对每条咨询标记来源、商品、身份、使用场景、状态、交付版本、首次运行和反馈；不将客户敏感内容放入公开站点或分析工具。
- 发布3篇与首个产品互相链接的教程/案例内容，所有案例必须去敏并标明证据范围。

### 第31–60天：验证愿付费与交付摩擦

- 对不少于10位目标用户做结构化需求访谈或人工咨询，记录购买意愿、拒绝原因与工具偏好。
- 完成首批付费或课程权益交付；每次使用同一份交付清单。
- 对已交付用户在第1天、第7天分别回访“是否安装”“是否完成首次运行”“卡在哪一步”。
- 从问题中只选择一个最高频阻塞项，修订 Skill、模板或安装说明并发布新版本。
- 争取完成1个教育或跨境团队的“AI 场景诊断 / 7天验证”协作试点；试点必须先确定数据授权、人工审核、验收范围和案例公开许可，不能以 Mock 演示替代最终交付。

### 第61–90天：沉淀案例并决定扩张顺序

- 以用户授权为前提，整理3个去敏成果案例：起点、使用场景、交付内容、人工审核点、实际限制和用户反馈。
- 用咨询量、首次运行率、支持耗时和付款/权益完成率，排序3个产品的下一步：继续、修订或停止。
- 仅对通过验证的产品开放销售；把未通过产品保留为候补或下线。
- 确定第4–6月的10个候选产品，以咨询和案例证据排序，而非凭主观热度。

## 6. 最小运营数据模型

团队使用一个私有台账，不在静态网站内保存真实客户资料。字段如下：

| 字段 | 用途 | 保存限制 |
|---|---|---|
| 线索编号 | 避免用姓名做主键 | 随机编号 |
| 来源与产品 | 判断内容和产品效能 | 仅记录公开页面/产品标识 |
| 身份与场景摘要 | 匹配交付 | 不记客户机密、真实订单或密钥 |
| 联系状态 | 新咨询、已回复、已核验、已交付、已关闭 | 授权团队可见 |
| 版本与交付时间 | 支持更新和追踪 | 只存产品版本与日期 |
| 首次运行与反馈 | 验证产品 | 记录结构化结果，不公开原始材料 |
| 案例授权 | 决定是否可引用 | 默认否，必须显式同意 |

## 7. 经营仪表盘

每周固定复盘，不以单日波动做重大决定：

- 公开触达：教程/案例/详情页浏览、来源、目录到详情点击率；
- 意向质量：有效咨询率、咨询产品分布、目标工具分布、未成交原因；
- 交付质量：首次回复时长、首次运行率、支持耗时、重复问题比例；
- 商业验证：付款或权益核验完成率、单产品净收入、续购/转介绍信号；
- 产品证据：每个产品的演练记录数、外部使用人数、版本更新与未解决风险。

不将客户输入内容、API Key、订单数据或可识别信息上报至分析平台。

## 8. 决策节奏与停止条件

| 节奏 | 决策 |
|---|---|
| 每周 | 审查新咨询、交付阻塞、FAQ、数据安全事件 |
| 每月 | 按证据确定一个产品继续、修订、候补或停售 |
| 每季度 | 审查阶段门槛和产品组合，不达标则缩小范围、提高交付质量 |

任一产品出现以下情形必须停止销售并复核：发现密钥/客户数据风险；安装关键路径无法复现；持续低于70%的首次运行率；承诺与实际内容不一致；无法提供必要的人工审核边界。

## 9. 非目标与外部依赖

本路线不自动代替支付、合同、税务、隐私合规、广告投放或客户沟通。达成1,000名客户/学员必须依赖团队实际运营：对外发布、人工回复、支付/资格核验、交付、回访以及取得案例授权；这些动作不能由静态网站或本代码库单独完成。
