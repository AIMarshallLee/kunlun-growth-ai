# PRD：昆仑增长 AI Skill 小课包商店（第一期）

**状态：** 已确认，待开发  
**产品：** skill.kunlungrowth.cn / 昆仑增长 AI 实战平台  
**版本：** 1.0  
**范围：** 面向对外客户与学员的付费下载与人工交付；首个垂直为跨境电商。

## 1. 摘要

在现有“昆仑增长 AI 实战”网站中新增 Skill 小课包商店。客户可以了解一项可复用 AI 工作流，购买包含 Skill、教程、模板和示例的完整小课包；课程学员可获得对应 Skill 作为课程权益。

第一期不建设在线 Agent、自动支付、自动发货或会员系统。网站负责清楚展示和收集购买意向，订单确认与交付由人工完成，以最快速度验证真实付费需求。

## 2. 联系人与职责

| 角色 | 负责人 | 职责 |
|---|---|---|
| 产品负责人 | 昆仑增长团队 | 决定选题、价格、上架与停售 |
| 内容负责人 | 昆仑增长团队 | 编写教程、模板、案例与更新说明 |
| 技术负责人 | 昆仑增长团队 | 维护网站、下载包、表单与数据安全 |
| 交付负责人 | 昆仑增长团队 | 核验付款、发送资料、处理安装与使用问题 |
| 客户/学员 | 外部用户 | 提供使用场景，完成购买与反馈 |

## 3. 背景

团队已积累跨境电商和教育方向的教程、可复用 Skill 及真实工作流，例如商品素材生产。若只留在本地或一次性对话中，这些成果难以被客户发现、购买、安装和复用。

现有平台已面向全球中文用户，并以 AI × 跨境电商为首个赛道，已有教程、案例和联系入口。现在可以把经过验证的 Skill 包装成“小课包”：用户既拿到工具，也知道输入什么、如何运行、如何判断输出是否可用。

## 4. 目标

### 产品目标

让有跨境电商实际任务的客户，在 5 分钟内判断一个小课包是否适合自己；让已购买用户在收到资料后能自行安装并完成第一次可用产出；让团队用人工交付低成本验证选题、价格和支持工作量。

### 首期关键结果

| 目标 | 衡量方式 | 首期目标 |
|---|---|---|
| 上架能力 | 可公开访问、内容完整的商品页数量 | 3 个首发小课包 |
| 购买线索 | 有效购买咨询 / 商品页访问 | ≥ 3% |
| 交付效率 | 已确认订单在工作时间内的首次人工回复 | ≤ 1 个工作日 |
| 首次成功 | 获得资料后反馈“完成首次运行”的用户占比 | ≥ 70% |
| 内容质量 | 因交付说明不清而需重复发送资料的订单占比 | < 10% |

这些是验证指标，不是对客户承诺的业务收益或销售结果。

## 5. 市场与用户

### 主要用户

1. **跨境电商经营者和运营人员**：需要快速制作商品内容、做多语种本地化或检查商品素材，但没有时间从零研究 AI 工作流。
2. **跨境电商服务商和小团队**：需要把重复交付流程标准化，降低新人上手成本，并保留人工审核。
3. **课程学员**：需要在教程之外得到可运行的工具、模板和练习，完成可展示作业。

### 核心任务

| 用户任务 | 当前痛点 | 小课包提供的价值 |
|---|---|---|
| 为商品制作内容 | 模型、提示词和素材步骤零散 | 提供事实表、提示词、镜头清单和质检门槛 |
| 做跨境本地化 | 直译会带来尺寸、合规与市场表述风险 | 把来源事实、缺口和人工确认分开 |
| 教学或培训 | 学完概念却无法完成作品 | 提供安装包、练习素材和验收标准 |

### 不服务的需求（第一期）

- 不承诺自动生成可直接投放的媒体资产；
- 不托管客户 API Key、商品数据、订单数据或用户生成内容；
- 不提供法律、税务、医疗、金融或合规结论；
- 不出售“保证涨销量”“自动赚钱”等结果承诺；
- 不提供自动付款、自动授权下载、订阅会员或在线 Agent 执行。

## 6. 价值主张

用户购买的不是一份提示词，而是一套可验证的交付方式：

- **Skill**：告诉 Codex、WorkBuddy 或兼容工具在何种场景下怎样完成任务；
- **教程**：从准备到首次运行的清晰步骤；
- **模板**：产品事实表、检查表、交付清单等可直接复用文件；
- **示例**：已去敏的输入和预期结构，帮助用户理解“好结果”是什么；
- **边界**：说明哪些事实不能推断、哪些环节必须人工审核。

相较于单独卖提示词或泛泛课程，小课包减少“买了不会用”的风险，也让课程收益可持续复用。

## 7. 解决方案

### 7.1 信息架构与用户流程

新增一级入口“Skill 小课包”，但保留现有实战教程、案例库、作品广场、AI 项目和企业挑战入口。

```text
首页 / 教程 / 案例
        ↓
Skill 小课包目录（跨境电商、教育；筛选与搜索）
        ↓
小课包详情页
        ↓
购买咨询表单（选择商品、使用场景、邮箱、同意联系）
        ↓
人工确认付款与交付方式
        ↓
发送下载包、安装说明、更新渠道与支持入口
        ↓
首次运行反馈 / 问题收集
```

课程页面可在对应课程下展示“本课程含 Skill 小课包”或“推荐搭配 Skill”，并链接到同一个详情页。课程权益由人工核验，不要求用户重复购买。

### 7.2 商品目录

首发只上架以下 3 个小课包；每个包必须先有真实演练或人工质检记录，才可标为“已验证”。

| 小课包 | 解决的问题 | 标准交付 |
|---|---|---|
| 商品素材生产 | 从已授权商品事实与源图，形成文案、镜头计划、视频分镜与质检清单 | Skill、商品事实表、素材计划模板、质检表、示例 |
| 跨境 Listing 本地化 | 将商品事实转化为目标市场的文案草稿，并显式标出缺口和人工确认项 | Skill、市场本地化 Brief、文案模板、合规复核表、示例 |
| 商品图/视频质检 | 在发布前检查商品身份、文字、变体、画面质量和文件交付完整性 | Skill、质检清单、问题分级表、交付 Manifest、示例 |

教育方向第一期先以“课程赠送权益”呈现，不另开大量教育商品。销量和反馈验证后，再独立上架“课程设计与作业反馈 Skill”。

### 7.3 详情页需求

每个详情页必须包含以下固定区块：

1. 名称、适用对象、要完成的任务和不适用场景；
2. 可交付物清单与支持工具（如 Codex、WorkBuddy）；
3. 输入要求：需要的产品事实、源图、文件格式和授权范围；
4. 演示结果：去敏案例或清晰的输出结构，不能虚构客户成果；
5. 购买后获得什么：Skill 文件、教程、模板、示例、版本号、更新政策；
6. 使用边界：不包含模型费用，不上传 Key，不保证商业结果，需人工审核的事项；
7. 价格或“咨询报价”状态；
8. “购买 / 领取课程权益”按钮；
9. FAQ：安装、兼容工具、更新、退款与支持范围；
10. 最后更新时间和变更摘要。

### 7.4 购买咨询与人工交付

第一期按钮跳转至扩展后的联系表单，不直接接入支付。

表单必填字段：小课包、姓名或机构、邮箱、身份（客户/学员/服务商）、使用场景、当前工具（可选）、是否课程学员、同意按需联系。禁止填写 API Key、客户隐私数据、支付卡信息或真实订单数据。

后台最小订单台账字段：线索编号、商品、来源页面、联系信息、权益类型（付费/课程赠送）、付款或资格核验状态、交付版本、发送时间、支持状态、反馈。仅团队授权人员可见。

人工交付标准：

1. 核验订单或课程权益；
2. 发送对应版本的 ZIP/文件夹、安装说明和适用工具说明；
3. 记录已交付版本与时间；
4. 遇到客户数据或密钥，要求其在自己的环境中配置，不通过聊天或邮件收集；
5. 将常见问题沉淀到商品页 FAQ，不暴露用户信息。

### 7.5 内容包标准

每个发布包采用统一结构：

```text
skill-name/
├── SKILL.md                 # 入口与适用边界
├── references/              # 必要说明、质量门槛
├── templates/               # 可编辑模板
├── examples/                # 已去敏示例；不含客户数据或密钥
├── CHANGELOG.md             # 版本与兼容性
└── INSTALL.md               # Codex / WorkBuddy 安装与首次运行
```

包内不得包含 API Key、Cookie、令牌、客户文件、自动发布脚本或不明第三方二进制文件。每次发布前应在目标工具中验证安装、触发条件、主要输出与卸载路径。

### 7.6 技术要求

- 复用现有 Next.js 网站、导航、页脚和联系能力；
- 第一阶段公开内容可静态发布；联系表单在未配置 Supabase 时延续现有演示提示，在配置后写入受 RLS 保护的数据表；
- 每个小课包由本地受版本控制的源目录构建 ZIP；网站只展示公开元数据，不存储客户上传文件；
- 页面需兼容桌面和移动端，关键操作可用键盘完成；
- SEO 基础项：唯一标题、描述、结构化标题、公开案例的清楚来源标注；
- 统计只收集必要的公开漏斗事件：目录浏览、详情浏览、购买咨询提交、人工标记交付；不得记录客户输入的敏感内容到分析平台。

### 7.7 内容状态与验收

| 状态 | 含义 | 可公开销售 |
|---|---|---|
| 草稿 | 选题或内容未完成 | 否 |
| 已演练 | 有本地示例和内容自检 | 否，可做候补页 |
| 已验证 | 在目标工具完成真实场景演练且通过质量门槛 | 是 |
| 已更新 | 修复、兼容性或内容升级已记录 | 是 |
| 已停售 | 不再推荐或无法维护 | 否，保留历史说明 |

首发的“商品素材生产”只能标注为“已演练/已验证”的实际级别，不能把离线方案测试写成已生成媒体的成功证明。

### 7.8 非功能与安全要求

- 下载包与网站公开文件均不含密钥、客户数据或受限素材；
- 表单明确提示不得提交敏感信息，数据仅用于人工联系与交付；
- 内容修改有版本号、更新时间和变更摘要；
- 所有承诺使用清楚边界：AI 输出需审核，模型费用另计（如适用），不保证经营结果；
- 发生错误时，表单不丢失用户已输入的非敏感内容，并给出人工联系替代方式；
- 仅在用户确认时上传、发送、发布或对外执行动作。

## 8. 假设与待验证项

| 假设 | 验证方式 | 失败后的处理 |
|---|---|---|
| 用户愿意为“Skill + 教程 + 模板”付费 | 比较商品页咨询率与实际付款率 | 调整定位、案例或改为课程权益 |
| 3 个跨境选题有清晰需求 | 记录咨询商品、场景和未成交原因 | 停止低需求选题，按反馈重排 |
| 人工交付可支撑首期 | 跟踪首次回复、交付耗时与支持工单 | 补充 FAQ、模板，之后再自动化 |
| 客户愿意使用 Codex/WorkBuddy | 记录工具偏好和安装成功率 | 增加兼容工具说明或提供替代格式 |
| 教程赠送能提高课程价值 | 比较有/无权益的转化与完课反馈 | 调整权益范围而非扩大功能 |

## 9. 发布范围与优先级

### 第一版（必须）

- Skill 小课包目录页；
- 3 个详情页；
- 扩展后的购买咨询表单；
- 统一的内容包结构、版本与交付台账；
- “商品素材生产”小课包的可售版本（完成内容包标准后）；
- 课程页到小课包的权益说明链接；
- 基础访问和咨询漏斗统计；
- 隐私、使用边界和人工交付说明。

### 第二版（验证后）

- 自动付款和订单确认；
- 受控下载页与版本更新提醒；
- 课程权益自动核验；
- 教育方向独立小课包；
- 评价和案例投稿机制。

### 不在近期路线图

- 在线 Agent 执行；
- 用户 API Key 托管；
- 自动生成、自动投放或自动发布商品素材；
- 订阅会员、分销、复杂优惠券和多币种结算；
- 用 AI 自动作出合规、财务或经营决定。

## 10. 验收标准

第一版在以下条件全部满足时才可发布：

1. 目录页能按“跨境电商 / 教育”浏览，首发 3 个商品卡片均链接到独立详情页；
2. 每个详情页覆盖第 7.3 节的 10 个固定区块，且没有未证实结果承诺；
3. 购买咨询表单会带入或可选择商品名称，阻止空必填字段，并显示不要提交密钥或客户敏感信息；
4. 未配置后端时，用户清楚知道表单为演示状态；配置后端时，提交只能由授权人员读取；
5. 每个可售 ZIP 使用第 7.5 节结构，通过人工的“无密钥、无客户数据、安装可读、版本可追溯”检查；
6. 商品素材生产小课包完成一次端到端演练，并把真实状态记录为“已演练”或“已验证”；
7. 用户在不接触团队内部文件的前提下，能根据 INSTALL.md 找到安装位置、完成一次首次运行或知道缺少什么；
8. 移动端能浏览目录、打开详情和提交咨询；
9. 站点的原有教程、案例、作品、项目和企业挑战入口不受影响；
10. 发布前完成链接检查、移动端检查、表单演练、下载包检查和内容事实复核。

## 11. 风险与应对

| 风险 | 应对 |
|---|---|
| 把 Skill 夸大成全自动 Agent | 所有页面明确输入、依赖、人工审核和未覆盖边界 |
| 客户上传或发送密钥/隐私数据 | 表单提示、字段限制、交付流程中只要求本地配置 |
| 首批选题卖不动 | 先人工交付、小批量测试，依据咨询原因更新选题 |
| 支持成本过高 | 用 INSTALL、示例、FAQ 和兼容性表减少重复答复 |
| 用户工具环境不同 | 明示支持范围，将兼容性作为版本字段，不作未测试承诺 |
| 课程权益混乱 | 台账中单独记录权益来源和交付版本 |

## 12. 开发顺序

1. 定义 3 个商品的公开元数据和首个可售内容包标准；
2. 建立目录页、详情页和导航入口；
3. 扩展联系表单与人工交付台账；
4. 将课程与对应小课包互相链接；
5. 补齐安装说明、FAQ、变更记录和案例；
6. 用一名非开发者按首次运行路径演练；
7. 小范围公开，依据咨询、付款、交付和首次成功反馈迭代。

## 13. 发布决策

产品负责人在以下情况下批准首发：3 个详情页完成、至少 1 个可售内容包通过端到端演练、购买咨询和人工交付路径可用、所有安全与事实检查通过。若这些条件未完成，页面可以作为“即将推出”展示，但不得收款或承诺交付日期。
