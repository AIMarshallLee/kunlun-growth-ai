# 输入、输出与失败合同

**合同版本：** 1.0  
**适用包版本：** 1.0.0

## 1. 必需输入

一次业务运行必须提供：

- `source_market`、`target_market`、`target_language`、`target_channel`；
- 当前 SKU 或变体的稳定标识；
- 至少一项商品事实，以及每项事实的来源、适用变体和证据等级；
- 需要生成或审核的 Listing 区段；
- 语言审核人、渠道政策负责人和业务发布负责人三项具名责任；
- 目标渠道当前规则的授权来源，或明确记录该来源仍缺失。

必需字段为空、配置无法解析、证据等级不在固定枚举中，均属于无效输入。

## 2. 可选输入

- 品牌语气、已批准术语、禁用说法和需复核术语；
- 当前 SKU 的包装、标签、规格表、实测记录和已批准品牌词表；
- 长度、格式、单位或文件名等交付限制；
- 负责人已经记录的审核决定。

竞品页面、搜索摘要和其他 SKU 只能帮助识别词汇或资料缺口，不能作为当前商品事实。

## 3. 事实证据等级

| 等级 | 定义 | 对公开主张的作用 |
|---|---|---|
| `authorized` | 由有权提供者明确授权，且可追溯到当前 SKU / 变体的事实 | 可进入主张审核；不自动免除语言、渠道或法律复核 |
| `observed` | 从已授权实际文件或资产中直接观察到，但尚未由事实负责人批准公开使用 | 只能进入内部记录；由具名负责人确认后才能升级 |
| `unverified` | 来自未核实说明、二手资料、生成内容或无法确认适用变体的信息 | 不得进入候选稿 |
| `unknown` | 缺失、冲突或没有可靠来源 | 不得进入候选稿 |

等级不得由 Agent 自行向上升级。每次升级都要记录授权来源、负责人和决定。

## 4. 主张状态

| 状态 | 定义 | 候选稿规则 |
|---|---|---|
| `approved` | 当前 SKU 的 `authorized` 事实直接支持，且所需人工判断已记录 | 可以进入候选稿 |
| `blocked` | 缺少证据、证据冲突、来源不适用或证据直接否定该主张 | 不得进入候选稿 |
| `review` | 有来源，但翻译、市场、渠道政策或法律判断尚待具名负责人决定 | 决定前不得进入候选稿 |

`blocked` 必须同时记录 `block_reason`：`missing_evidence`、`conflicting_evidence`、`contradicted_by_evidence` 或 `wrong_variant`。缺证据与证据证明主张不成立不得混写。

## 5. 固定输出

每次运行必须按以下顺序交付，即使运行被阻塞：

1. **Claim Ledger**：主张、来源、证据等级、变体、状态、阻塞原因、审核人或缺口负责人；
2. **Blocking Gaps**：缺口、阻塞原因、负责人和所需下一份证据；
3. **Internal Market Draft**：只使用 `approved` 主张；无效输入时写 `not_generated`；
4. **Human Review Checklist**：语言、渠道政策和业务发布决定及具名责任；
5. **Channel-ready Candidate**：满足发布公式时给出候选，否则写 `not_ready` 或 `not_generated`；
6. **Delivery Manifest**：输入路径、输出状态、失败代码、未解决项、审核记录和最终决定。

## 6. 最终状态与发布公式

最终状态只有：

- `ready`：可交给具名业务负责人进行人工发布；
- `not_ready`：不得发布。

只有同时满足以下条件才能标记 `ready`：

- 候选稿中的每条公开主张都是 `approved`；
- 每条 `approved` 主张都由当前 SKU / 变体的 `authorized` 事实支持；
- 未解决的 `blocked` 和 `review` 主张均为 0；
- 发布所需字段和当前渠道规则来源完整；
- 具名语言审核人、渠道政策负责人和业务发布负责人均记录批准决定；
- 内部备注、未知字段和补数提醒未进入候选稿。

任一条件不满足，Manifest 必须为 `not_ready`。

## 7. 失败处理

| `failure_code` | 触发条件 | 必需行为 |
|---|---|---|
| `invalid_config` | `config.json` 缺失必要键、JSON 无效或枚举值无效 | 不生成草稿；列出无效字段、修复方法和配置负责人 |
| `invalid_input` | 必需业务输入为空、无法对应当前变体或格式不可读 | 不生成草稿；列出缺失字段和输入负责人 |
| `insufficient_evidence` | 事实为 `unverified / unknown`，或缺少发布所需事实 | 保留 Claim Ledger 和阻塞项；候选稿为 `not_ready` |
| `review_required` | 存在未决定的 `review` 主张或缺少人工批准 | 指明具名审核人和所需决定；候选稿为 `not_ready` |
| `capability_unavailable` | 宿主无法读取必要文件或完成要求的语言 / 文件处理 | 说明缺失能力和人工下一步；不得伪造已经读取或完成 |

多项失败同时存在时全部记录。失败不改变固定输出结构，也不得用空白、推测或同类商品常识制造可发布结果。

## 8. 审核责任

- **语言审核人：** 负责语义、术语、单位和目标语言自然度；
- **渠道政策负责人：** 负责使用授权的当前来源核验渠道字段和规则；
- **业务发布负责人：** 负责确认商品事实授权、风险接受和是否发布。

每项责任记录实际个人姓名或可审计身份、决定和日期。仅写团队名称或“已审核”不构成具名批准。

## 9. 安全与非目标

本包不要求密钥，不自动联网、上传、发布、覆盖或删除客户资产。它不保证平台审核、排名、转化、销售或法律合规，也不替代专业翻译、法律或渠道判断。
