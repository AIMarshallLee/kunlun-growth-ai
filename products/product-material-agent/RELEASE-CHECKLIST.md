# 1.0.0 发布检查清单

所有项目均需由对应负责人记录后才能发布包或客户材料。未勾选项目不是默认通过。

## 包完整性负责人

- [x] `manifest.json` 的版本、入口、合同、配置、公开样例和测试命令正确。
- [x] 根文件以及 `templates/`、`references/`、`examples/`、`tests/` 均存在且非空。
- [x] `node verify.mjs` 返回 `PASS`，复制 `config.json` 后仍通过。
- [x] `CHECKSUMS.sha256` 覆盖除自身和本地 `config.json` 外的全部发布文件且哈希匹配。
- [x] JSON 可解析，Markdown 无未完成标记、真实客户数据或虚假市场数据。
- [x] 密钥扫描没有发现凭证，包内没有环境变量文件或账号数据。

## 每次客户任务清单（交付时填写）

## 事实审核负责人

- [ ] 每个文案事实均为 `authorized`，来源 ID 与变体范围可追踪。
- [ ] `observed`、`unverified`、`unknown` 没有作为可发布主张。
- [ ] 缺失证据与证据冲突分别记录。

## 素材授权与品牌审核负责人

- [ ] 源资产路径、授权用途、人物授权和客户交付范围已确认。
- [ ] 图片计划与视频分镜保持真实产品身份，没有新增 Logo、配件、人物或演示。
- [ ] 品牌语气、视觉规则、渠道约束和禁止说法已检查。

## 发布决策负责人

- [ ] 六项固定输出完整，所有阻塞项已关闭。
- [ ] 工作流状态为 `ready_for_review`，人工审核记录完整。
- [x] 已明确本包不会自动联网、付费、上传或发布。
- [x] 已披露真实客户运营数据尚无可验证记录，不宣称市场成熟。
- [ ] `releaseDecisionOwner` 亲自记录 `approved` 或保持 `not_approved`。
