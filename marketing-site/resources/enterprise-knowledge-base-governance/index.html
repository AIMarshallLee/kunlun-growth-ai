知识治理 / Enterprise Knowledge Base

企业知识库怎么维护、
怎么做权限？

知识库的价值不在存了多少资料，而在业务人员和 AI 都能在允许的范围内找到可靠输入、理解适用边界，并知道谁负责更新。没有这些前提，接入 Agent 或 Workflow 只会放大混乱。

先从一条业务流程定义知识

不要从全公司文件迁移开始。先选一条需要稳定知识支持的流程，例如销售回复准备、项目交付问答、内容审校或新人上手。围绕真实任务列出：需要回答什么、当前资料在哪里、哪些内容容易过期、谁最了解、谁有权决定公开范围。

资料权限要在入库前说清楚

  1. 来源：每条关键知识都应能回到原始资料、负责人或决策记录，不把无法解释出处的内容当作标准答案。
  2. 可见范围：区分公开、内部、项目或客户专属资料；范围不清的材料先保留在原位置，不默认进入通用知识库。
  3. 使用边界：明确哪些资料可以供检索、摘要或生成候选内容，哪些不能用于 AI 试点、对外表达或跨团队复用。
  4. 过期处理：对政策、产品、价格、项目状态等会变化的信息设置复核时间和失效标记。

维护责任不能交给“所有人”

每个知识域至少要有一个业务 Owner：负责确认内容是否仍适用、处理冲突、指定更新节奏，并在关键规则变化时通知使用者。内容整理人员可以辅助归档，AI 可以生成摘要和更新候选，但都不能替代 Owner 对事实和可见范围的判断。

用真实问题检查是否可用

知识库上线前后，都用实际工作中的问题测试：能否找到相关资料？回答是否回到正确来源？是否遗漏了限制条件？不同人按同一规则是否能得到一致结论？当答案不可靠时，应记录缺口并回到资料、结构或责任边界，而不是仅靠更换模型。

什么时候再接入 Agent 或 Workflow

当一个知识域的来源明确、权限清楚、维护有人负责，并且已在真实任务中证明“找得到、用得上、能复核”之后，才适合把它作为 Agent 或 Workflow 的输入。接入后仍应保留最小权限、人工审核和可追溯记录。
