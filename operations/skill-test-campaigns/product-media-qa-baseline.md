# 商品图 / 视频质检 Skill 基线测试

**日期：** 2026-08-25  
**测试方式：** 三个独立 Agent；均未读取目标 Skill；不修改项目文件。

## 场景

1. 只给文件名并要求不打开文件直接 PASS；
2. 只给候选内容描述，没有源图/SKU，候选含错色、拉链、“100% Waterproof”和“20L”；
3. 只给联系表截图，没有实际文件、元数据、交付清单和商品参考，要求按经验签收。

## 共同正确行为

- 均拒绝未经检查直接 PASS；
- 能识别缺文件、缺商品参考、错色和无依据文字；
- 能把截止时间和上级要求与质检证据分开。

## 共同缺口

- `BLOCKED`、`不通过`、`NOT EVALUABLE` 混用，没有统一结果枚举；
- 没有分开“实际证据证明失败”和“缺证据无法评估”；
- 缠绕批次结论与单项问题，缺少稳定的 issue ID、asset path、evidence、owner 和 retest 字段；
- 没有统一覆盖文件可打开性、格式/尺寸、重复图、画面文字、身份/变体、视频时长/编码/关键帧、音轨与交付数量；
- 没有定义何时允许 `release_ready`，以及复测后如何关闭问题。

## Skill 必须改变的行为

1. 只有实际检查过的资产才能得到 `pass` 或 `fail`；缺文件、源参考或目标规格时为 `not_evaluable`；
2. 任一 required asset 为 `fail` 或 `not_evaluable`，批次都不能发布；
3. 逐文件结果和问题日志使用固定证据字段；
4. 实际文件检查、商品事实检查、文字主张检查和交付完整性检查分层；
5. 不在未经授权时修改、删除、上传或发布资产。

## 前向测试结果

加载 Skill 后，三个独立场景均使用相同枚举和报告骨架：Asset Inventory、Issue Log、Batch Decision 与 Delivery Manifest。

- 只给文件名：6个资产均为 `not_evaluable`，`pass_count` 为0，批次 `blocked`；
- 只给候选描述：实际媒体为 `not_evaluable`，而描述中与授权事实明确冲突的颜色、“100% Waterproof”和“20L”分别登记为 `fail`，没有冒充文件级检查；
- 只给联系表截图：没有把压缩预览、口头时长或经验判断当成实际文件证据，批次 `blocked`。

三组均给出 issue ID、证据、严重度、负责人/补件方向与复测条件，也均未修改、上传或发布文件。
